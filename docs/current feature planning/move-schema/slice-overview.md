# Move schema (#2): branch overview

Branch: feature-test/new-move-schema. Read this file first, then ONLY the slice-n.md you are working. Each slice file holds that slice's decisions and plan, so nothing here grows past a summary.
Schema spec: docs/MOVE-AXIS-SCHEMA.md. Design input for combat: docs/current feature planning/move-coverage-report.md (generated). Status updated: 2026-10-25.

## What this branch is
A ground-up move system. A single database of moves (the schema) is converted to JS, resolved into final move definitions, and consumed by a rewritten combat.js that dispatches on the schema axes (space, delivery, payload). The legacy `kind` label is not part of the new system and there is no bridge back to it. Move ids do not change, so saves stay compatible.

## File roles
1. docs/move_rework_holding/move-conversions-described.json: source of truth database (63 moves, Bubble excluded).
2. js/data/move-attributes.js: definitions and defaults (the grammar).
3. js/data/moves-generated.js: the database as usable JS (generated by tools/export_moves.js, never hand-edit).
4. js/data/move-overrides.js (new, slice 2): per-move overrides only, just the moves and fields Jess overrides.
5. js/data/move-handler.js (new, slice 2): special handlers (6 now, expandable), each declaring a trigger and optional condition.
6. js/data/move-resolver.js (new, slice 2): takes generated moves, overrides and handlers; applies defaults, derived values (cooldown from PP, damage from Power normalized by E), overrides and handler attachment; emits final move data. Eager at load.

## Decisions that span slices
- No legacy bridge, no derived `kind`, no flat projection in old field names (2026-10-25).
- combat.js will be mostly rewritten. Upgrades apply in combat.js on top of the resolver's base-normalized damage.
- Resolver timing is eager at load; individual-scope stat buffs apply to the active team member only; Bubble is deprecated and removed in the forgotten-move purge. Details: slice-1.md and DECISIONS.md 2026-10-25.
