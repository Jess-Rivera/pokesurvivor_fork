## Plan decisions (recommended; approved with this plan)
- P1 Routed list: add exactly fire-spin, leaf-storm, night-shade (24 routed in total). The list stays in js/systems/move-route.js only. Flag off, the game is unchanged.
- P2 Deep-freeze G.MoveDefs. In move-resolver.js, right after G.MoveDefs is assigned, freeze the whole structure recursively (arrays and nested objects). Do not freeze G.MoveData, overrides or handlers unless the harness shows they need it. Resolve itself must keep returning fresh objects for tools. Report each hit and fix it by copying, not by weakening the freeze. A write to a frozen def must fail loudly in the harness, so confirm the files involved run in strict mode, or add an explicit check in the harness that proves a write is rejected.
- P3 Validator rules (review 2.4, ten rules). Audit each against the existing rule list and add only what is missing, in the same data-driven style, with a clear msg each. The ten: (1) persistent with a cd, or without endOn notActive; (2) a non-persistent move with no cd after resolution (this one belongs in the resolver or the --resolved check, since cd is derived there); (3) pierce on a shapeless move or an emitter parent; (4) turnRate or aimTrack with targeting direction or none; (5) trigger contact together with endOn time 0; (6) hitPolicy interval with a lifetime shorter than rehit; (7) emit count above 1 with trigger termination or enemyHit; (8) grow.dim radArc on a shape already at 2 pi, or grow.max below the start size; (9) a stat effect with side foe and scope team; (10) returnHits without a turnaround (check overrides too). Run the validator on all moves, resolved too, and LIST every violation before touching data. Do not edit move data to make a rule pass without telling Jess which move and why (if a violation is a real data bug, a fix is a flagged data edit via the source JSON plus regenerate, like 4a and 4b; if the rule is wrong for that move, stop and say so). Add one failing fixture per new rule to the validator tests so a regression is caught.
- P4 R7 persistent upkeep (move-sim.js). Add the upkeep pass named in the architecture (upkeepPersistent, section E). For each routed persistent slot, each frame: if the slot is in the active group and the owner is not stunned and no live instance group exists for that slot, spawn one; if the slot has left the active group, or the owner is stunned, end its live instance with reason notActive. Persistent slots never use the cooldown timer. Define the unit: the count shapes of one slot form one group spawned together (Fire Spin 3, Leaf Storm 4); R7 counts groups, one per slot. If architecture C4 or the 3c code models count differently (for example one instance per shape), follow the existing model and make the harness count in the same unit, and say which in the finish report. Use the same "stunned" and "active group" notions the cast path already uses (find the existing checks in castSlot and the 3d code; do not invent new ones). If the sim needs a swap notification and none exists, derive it by comparing the slot's membership in the active group each frame; if that is impossible without editing player.js, STOP and tell Jess. A swap away must end the instance in the same frame the group changes, and a swap back must create a fresh instance with fresh hit records and a fresh orbit phase.
- P5 Orbits (move-sim.js step functions and move-geom.js only). Per D25: shape i of count has angle phase + angularSpeed x age + 2 pi i / count, position = the owner position (anchor caster, R8: recomputed from the owner every step) plus orbitRadius x (cos, sin). Phase starts at 0 at spawn. The collision test is a true circle of the shape's own radius against the enemy (D17 style, but test against the current step's position, and use a swept segment between the previous and current position of the shape so a fast orbit cannot skip an enemy; Leaf Storm moves 475 px/s at its rim, close to 8 px per frame at 60 fps, so this matters). The orbit radius goes through the lens in shapeOf: orbitRadius x moveRadiusMul (D36 gains this term; the orbiting shapes' own radius already scales). Hit policy interval, rehit per enemy per instance as in 3c; the first hit lands as soon as an enemy is inside. Pierce unlimited, no exhaustion. An orbit has no endOn time, so the instance lives until notActive, owner death or run end. The instance ends cleanly on owner death and on run restart (no leaks).
- P6 Fire Spin and Leaf Storm payloads: no new effects. Fire Spin applies damage, burn and the 4a trap root through the existing appliers; check the accuracy fold-in (D1) gives basePower 35 x 85 / 100. Leaf Storm's self Sp. Atk -2 uses the 4a/4b stat applier with the per-Pokemon source tag and maxStacks 1, so it renews and holds at -2, never -4, and its 6 s duration refreshes on each hit.
- P7 Night Shade: persistent static circle anchored to the caster (follows the owner every step by R8), radius 120 through the lens, interval 0.5 s per enemy, payload special levelDamage (the 4b handler: dmg equals the owner's level, flat, no STAB, no type, no crit, no other multiplier, floor 1, through the normal enemy hurt path, shields absorb it). No target cap. Cast gate: none targeting never waits (R9). Do not change its data.
- P8 Render (move-render.js, presentation only): orbit shapes drawn with the y squash of 0.7 around the owner (rendering only, the sim stays a true circle), Night Shade drawn as a soft ring of radius 120 that does not obscure the player (a faint fill and an outline, like other circle moves), Fire Spin and Leaf Storm shapes drawn as small sprites or the existing generic shape draw, whichever the renderer already uses for routed radial shapes.
