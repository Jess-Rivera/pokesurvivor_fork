## Decisions (accepted)
- D1 routed list: exactly the 7 canaries, tackle, ember, water-gun, hydro-pump, heat-wave, mud-shot, flamethrower. aura-sphere and hyper-voice stay out for now. The list lives in ONE place and grows with each slice.
- D2 props: moves damage props; solid destructible props spend pierce like legacy; grass never does. The cast gate stays enemy-only, so a routed move will not smash an idle rock or chest by itself (legacy targets one within 200 px when no enemy is near). Record that as a backlog issue draft.
- D3 Tackle reach: leave the 3c reach as built (48 px plus target radius, no player-body term). Judge by feel. If Jess finds it short, the fix is a data change to Tackle, never a new rule.
- D4 boss priority for ranged moves: stays gone (S3). Backlog note only.
- Flag: ?newcombat counts only when ?dev is also present, so a published build can never turn it on.

## Build (all behind the flag; flag off must behave exactly as today)
1. Wiring. Add script tags to dev.html and names to the NEED array for the data chain (attributes, generated data, overrides, handler, resolver) and then move-geom, move-sim, move-effects, move-render, in dependency order after the files they use (stats, types, stages, status, weather, world, enemy, vfx). The files load always but stay dormant without the flag.
2. Routing predicate. Give G.MoveSim a way to receive an "is this move id routed" check. The default is allow-all, so the 3c harness and mutation runner are unchanged. The game passes the check built from the single supported list. Slots the check rejects are never touched by the sim. Add a harness case for the filter.
3. Legacy skip. In combat.js tick, skip routed slots in BOTH loops (inactive recharge and active tickMove), and only when the flag is on. The slot timer t is owned by exactly one system per slot. This is the riskiest edit: keep it tiny and re-run every harness.
4. game.js. When the flag is on: each frame pass the camera view rectangle to G.MoveSim.setView, call G.MoveSim.tick(dt, pl, time) right after G.Combat.tick (the 3c contract), and draw G.MoveRender in the ground and air layers next to the legacy field draws. G.Combat.resolve keeps enemy shots, wall cover and contact damage. Single-player only: skip Coop.cast for routed casts and note it.
5. Slots and HUD. Routed slots gain new fields with null-check defaults so swaps, bonds, the sheet and saves keep working; old saves load without clearing; the save format is unchanged. The HUD ring for a routed slot divides by the resolver's cd (a field the glue sets, read with a fallback to the legacy cd). New-path moves ignore upgrade cards until slice 5.
6. Cast glue (presentation). Subscribe once to 'move:cast': find the player's routed slot by move id, call Player.cast on it (animation, sound, Life Orb cost keep working) and set castAt for the HUD flash. This lives in move-render.js or the game wiring, never in the sim (I8).
7. Props in the sim. Props enter the same sorted candidate list as enemies (G.World.propsInCircle, G.MoveGeom.contains, one geometry implementation, I6). Hit policy and the pierce budget apply as for enemies, except grass never spends pierce. Damage uses the legacy prop formula. Props emit no 'move:hit' (that event stays enemy-only, so overlay flashes appear only on enemies). Update the harness world stub and add cases: a rock in a sweep takes damage, a solid prop spends pierce, grass does not, and an enemy behind a solid prop at pierce 0 is not hit.
8. move-render.js (G.MoveRender, drawing only, reads the instance list read-only, never writes). Outline-quality shapes in the move's type color from G.MoveGeom.shapeOf, and the retained patch and telegraph recipes from drawGroundFields and drawAirFields chosen by phase and geometry, not kind (I1: avoid the word kind in every new move-*.js file, comments included; check.js guards it).
9. Hitbox overlay. A dev toggle (a G.Debug function, ?dev only) draws shapeOf for every live instance and flashes on 'move:hit'. Same geometry as the sim, no second implementation.
10. Quick-test helper in debug.js: one call that loads the 7 canaries into the slots (use loadout) and places still dummy enemies at set distances around the player, so Jess can check all seven in about a minute. If the existing spawn API cannot freeze enemies, say how you solved it. Use skipTo for the density check.
11. Performance. G.MoveSim.step scans every enemy each frame for the largest radius. If the flag-on framerate at the same skipTo minute is visibly worse than flag-off, fix it now (cache it per frame); CLAUDE.md says a visible collapse is a feel problem, not a micro-optimization.
