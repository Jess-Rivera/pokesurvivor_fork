Source of truth for the schema: docs/MOVE-AXIS-SCHEMA.md. Raw database: docs/move_rework_holding/move-conversions-described.json (63 moves, all reviewed, single file).
Each slice gets its own chat. This file is the handoff: read it, then the one slice you are working on.

## Architecture (Jess's model)

1. Raw database: the JSON above. Stays single-file.
2. Export script (in tools/): converts the JSON into a generated js/data move file (the game loads scripts, it does not fetch JSON). Never hand-edit the output.
3. Handler (new js file): owns everything the schema adds that is not plain data, such as the special handlers (berrySteal, fixedDamage, chainDamageFalloff, levelDamage, statusBonus, setWeather) and later emit and other new features. It keeps that logic out of both the resolver and combat.js.
4. Resolver (new js file): a pure fold. Takes the generated move data and the handler, applies the layers in schema order (source facts, formulas, presets, hand overrides), and outputs the final resolved definition combat needs.
5. End state for combat.js: thin. An entity calls a move, the resolver supplies the resolved definition, combat applies "move does X to entity B" and emits the outcome.
Migration bridge: the resolver also outputs a flat projection in the old field names (dmg, cd, radius, arc, knock, count, pierce, speed, life, dur). Existing combat, upgrade cards (mechanics.js, kinds.js) and HUD keep reading it until the new executors replace them. Move ids do not change, so saves stay compatible.

## Decisions so far

- Cooldown and base damage are DERIVED (PP and Power). Formulas are written and calibrated in slice 2.
- Individual-scope stat buffs apply to the ACTIVE team member only (decided earlier). Built in slice 4.
- Emit: handled when slice 4 gets there.
- Bubble: deprecated (API description says "forgotten"), excluded from the schema pass, removed in the later forgotten-move purge.

## Settled in the slice 1 chat (2026-10-25)

- Resolver timing: EAGER at load (still the one pure fold, the same code check.js runs). Reason: gyms.js validates every gym move through Moves.BY_ID at boot and other readers use BY_ID as a plain property. Revisit with a measured 1000-move synthetic run in check.js. Real scaling cost is shipped data size, so the export drops defaults and we measure once it exists.
- Source of truth: docs/move_rework_holding/move-conversions-described.json only (63 moves, Bubble excluded via forgottenSkips). move-conversions-final.json never existed in git history; its reference is removed.
- Grammar lives in js/data/move-attributes.js. The presets file (move-classification.js) is deferred to slice 2, since all 63 moves spell out their geometry and none needs a preset.
- `kind` is NOT a schema field and is dropped from the export, inline emit moves included. Legacy readers (combat.js dispatch, the kinds.js upgrade key table, mechanics.js, icons.js, enemy.js boss casts, gyms.js BOSS_FORMS) get a DERIVED kind in the bridge projection only, computed from the axes in slice 2 and deleted in slice 7. The parity report lists every move whose derived kind differs from legacy (legacy has 15 kinds incl. chain, the described data had 14 hand labels).
- Grammar additions: grow.max and grow.per, stat chance/duration/maxStacks, casterState as the container for iframes and delay. `hitCap` is removed (artifact of an earlier schema pass). Already applied to docs/MOVE-AXIS-SCHEMA.md.
- Gyms share move definitions: gym.js and gyms.js use Moves.BY_ID, instance and addStack, and enemy.js boss casts read kind, cd, cat, radius and arc. The flat projection must therefore carry every legacy field its readers use (kind derived, cat, name, type, desc, stat, stageN, fixed, size, width, ailment fields), not only the ten listed in the architecture section.

## Slice 1 results (2026-10-25), DONE

- Built, groundwork only, nothing wired into dev.html: js/data/move-attributes.js (grammar), js/data/moves-generated.js (generated by tools/export_moves.js, never hand-edit), tools/validate_moves.js (self-test, validation, coverage buckets), docs/current feature planning/move-coverage-report.md (generated).
- Gate met: 63/63 moves valid, validator self-test 21/21, tools/check.js runs the export freshness check and the validator (pass and stale paths tested). dev.html and the NEED array wait for slice 3.
- Source fix made in described.json: metal-claw team buff now side self like Swords Dance, Agility, Harden. Spread values stay on count-1 moves (legacy ignores spread at count 1, but a count upgrade uses it); the executor disregards it, the data does not drop it.
- Spikes: the source is correct, a placed mine lasts until triggered (it detonates once on contact and is gone). A timeout is optional, so the grammar only requires some endOn.
- balanceClass stays in the export. `trigger` keeps one legal value set per location. Heal amounts accept both shapes.
- Pierce default is UNLIMITED when omitted; pierce 0 is one hit, pierce n passes through n enemies. All 24 shapes that stated no pierce were static or placed areas, so nothing changed. Then Psychic and Aerial Ace were set to omit it (they hit everything in their arc or landing circle), and Quick Attack keeps 0 (single target by default, so the pierce upgrade card lets it dash through enemies). Flag for slice 5: a pierce upgrade is meaningless on an unlimited move, so the derived upgrade keys should skip it.
- Export keeps default values (shortcut: small size win at 63 moves); drop them when the list grows.
- Not encoded: "area geometry rejects pierce" is moot now that unlimited is the default. The returns rule (point or linear shapes only) is encoded.
