=====================================================================
 4. DECISIONS FOR JESS (each one separate)
=====================================================================

  D1  BUMP STYLE   (new feature, nothing existing changes)
      proposed:  coin + number pop to ~1.3x and settle in ~0.18 s,
                 restarted on every gain, never queued
               + number rolls up like a slot reel toward the real value;
                 when the gap is big it closes faster (never lags > ~0.4 s)
      alt:       pop only, number jumps straight to the value

  D2  CO-OP RUNS   (cloud phase is deferred)
      proposed:  Silver counter hidden in co-op runs until co-op shops
                 exist. The co-op panel already uses the top-left
                 (hud.js line 578), so this also avoids a clash.
                 One-line note in TODO.md under deferred.
      alt:       show it, push the co-op panel down

  D3  WHICH KILLS PAY
      proposed:  every kill pays the same formula, including elites,
                 bosses and gym arena mons (spec says "each kill").
      alt:       bosses/elites pay a multiple (would be a new rule)

  D4  NO SOUND per coin (it would be spam at high kill rates).
      shop sounds are already TUNE for later per the spec.

 5. TESTS
=====================================================================

  NEW HARNESS   docs/proposals/silver-harness.js   (picked up by check.js
                automatically, since it matches *harness*.js)
     checks:
     - a run starts at 100; a second run starts at 100 again (no carry)
     - pay at 0:00 and 2:00 = 1 (the min), 5:31 = 1.0, 15:00 = 2.55,
       30:00 = 5.0, all hand-derived from the formula, not from code output
     - fractions add up: two kills at 15:00 = 5.10, whole shows 5
     - uses the plain run level: a run with escalation or gyms done pays
       the same as one without
     - remote enemies and an escaped thief pay 0
     - endRun: PokeCoins earned are identical with 0 and with 9,999 Silver
     - no new key appears in the save object after a run
     why new: no existing harness touches run-only currency, and the
     PokeCoin end-of-run maths is the one thing Silver must never leak into.

  MUTATION RUNNER   docs/proposals/silver-mutate.js   (run by hand, like
                    the other *-mutate.js files)
     breaks, one at a time, and expects the harness to FAIL each:
     - removes the min-1 floor
     - reads the bumped / gym-offset level instead of the plain one
     - rounds each kill's pay instead of keeping the fraction
     - adds Silver into the end-of-run PokeCoins
     - skips the reset at run start
     why: proves each harness check really bites.
