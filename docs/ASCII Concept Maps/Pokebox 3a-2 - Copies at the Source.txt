=====================================================================
 TODAY vs AFTER
=====================================================================

 TODAY (fill):
   source --> writes owned / shiny record --> commit --> normalizeTeam
                                                      --> G.Copies.fill makes a copy
                                                          ONLY if that species has none
   => a repeat makes no copy; a sold copy would come back on the next commit

 AFTER:
   source --> G.DB.obtain(dex, shiny, from)
                 |-- writes the Pokedex record (owned, and shiny if shiny)  [unchanged meaning]
                 |-- G.Copies.add: ONE new copy, every time, repeats too
                 '-- returns { isNew, copy }
   normalizeTeam no longer adds copies. fill is deleted.

 One helper so every source does the same two writes in the same order,
 and the harness can test it (db.js already loads in the copies harness).

 DECISIONS FOR JESS  (rule changes, each one approve or change)
=====================================================================

 D1  Gacha repeats pay NO coins from now on.             [Approved ruling, timing is new]
     Between 3a-2 and 3a-3 there is no way to sell, so repeats only fill boxes.
     REC: drop the refund now (keeping it would pay twice once selling lands).

 D2  A repeat gacha shiny is kept, not re-rolled.         [Approved ruling]
     Shiny hunting a missing species gets slower (the re-roll was a pity valve).
     REC: build as ruled.

 D3  Repeat rescue and repeat wild shiny.                 [Open in pokebox-plan]
     a) a copy, no coins        b) coins as today, no copy      c) a copy AND the coins
     REC: a). Same rule as the gacha, and a repeat now rolls new IVs and a new nature.

 D4  A shiny of a species you do not own gives ONE copy.  [NEW rule]
     Today: the shiny AND a free normal (fill made a copy for both records).
     After: only the shiny copy; the Pokedex still marks the species owned.
     REC: one copy. "You keep what you caught", and the free normal would be
     a hidden second copy per shiny.

 D5  Messages on a repeat (new English strings; new-species lines keep their inherited keys):
       rescue:      "<name> joined your box!"
       wild shiny:  "Another shiny <name>! Added to your box."
       gacha card:  "Repetido · coin +N"  becomes  "To Box N"   (the box it landed in)
     REC: as written.

 D6  Full boxes until 3a-4: unchanged (a new copy still overflows into the last box).  [REPLACED by 3a-4, 2026-11-04]
     REC: leave it; 3a-4 replaces it with the warning and auto-sell.

 D7  No safety net: a species that is owned but has no copy stays that way.
     Your save already has a copy for everything (fill ran on every commit).
     REC: no net, since a net is exactly what would bring a sold copy back.

 RIDE-ALONG FIX: TOP BAR COINS GO STALE
=====================================================================

 WHY (from the code, not reproduced in a browser here)
   the top bar number is drawn ONLY by G.UI.refreshCoins (js/ui/ui.js), called on:
     screen opens (chrome, Team, Settings, Shop refresh) | achievement rewards
     | cloud sync (G.DB.onSync)  <-- never fires on a LOCAL save
   so on a local save, coins that change while a screen stays open are not redrawn:

   coin write                         file                    redraws the top bar?
   ---------------------------------  ----------------------  --------------------
   buy a box (3a-1, mine)             js/systems/copies.js    NO  <- my miss
   gacha repeat refund (until 3a-2)   js/systems/gacha.js     only when results close
   team item / item slot buy          js/data/items.js        yes, via Shop refresh
   run coins banked                   js/game.js endRun       on the next screen open
   achievement reward                 js/systems/progress.js  yes
   G.Debug.coins                      js/core/debug.js        yes
   (3a-3 selling will be another)

 FIX: one hook, not one call per spot
   G.DB.commit (js/core/db.js) redraws the top bar after every save write,
   when the top bar is showing. Every coin write above already commits.
   No document or no G.UI (the Node harnesses): it does nothing.
   Existing precedent: db.js already calls G.UI.refreshCoins after a cloud sync.

 D8  Hook in G.DB.commit, so any future coin source updates for free.   REC: yes
     (alternative: a refreshCoins call at each spot, easy to miss again, as I just did)

 D9  The top bar formats coins in the Spanish style (12.000); the Shop and the
     box tabs use 12,000. Switch the top bar to 12,000 to match.        REC: yes
     (refreshCoins in js/ui/ui.js, one locale argument)
