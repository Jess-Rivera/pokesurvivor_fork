This batch adds ONE new path rule, so it is a rule change (grammar + runtime), not just data.

================================================================================
1. WHY A NEW FIELD
================================================================================
  path.curve      turns the heading at a constant rad/s. Constant turn + constant
                  speed = a CLOSED circle (radius = speed / curve). It never leaves.
  path.oscillate  a 1D sine offset ACROSS the heading only (D24). A wave, never a loop.

  A loop needs a 2D offset (along AND across) around a base point that keeps
  travelling straight. That is the same idea as oscillate (D24), one dimension up.

================================================================================
2. THE NEW FIELD: path.loop { radius, frequency }
================================================================================
  base point   travels straight along the aim at moveSpeed (unchanged travel)
  shot         base point + a circular offset, theta = 2 pi x frequency x age
                 along  = radius x sin(theta)
                 across = radius x (1 - cos(theta))
  at age 0 the offset is 0, so the shot starts on you like every other shot
  (no spawn jump), then circles to one side, same turning direction as today's curve.

     @ = you        the base point slides right at 170 px/s
     @-.     .-.
     |  \   /   \     loop 1 brushes past you, loop 2 is ~100 px further out
      '--'-'     '--> ends ~200 px out, 1.2 s

  exact and dt-independent (positional, like D24); composes with oscillate (offsets add);
  the base heading is not turned by the loop; the shot's velocity (vx, vy) is the true
  motion, so a travel-direction knockback and the render trail follow what you see.
