6. Building a WildMon

The Rust version of new Enemy(def, x, y, sc). Same steps in the same order, but the sim parts and the presentation parts come apart.

Today, entities/enemy.js constructor (trimmed)
Rust, sim/src/spawn.rs
What moved out: new G.Sprites.Animator(...) is gone from the sim. Godot sees a new entity with a Species and Body.scale in the next frame's buffer and builds its own animated sprite. bodyRadius comes from the GameData.body table, not the sprite sheet.
Why two steps: Rust won't let you hold a read borrow on the world (the tables) while you add to it. So you build everything first, the borrow ends, then you insert. JS lets you mix those freely, which is how presentation calls crept into constructors.
Why two tuples: readability, and Shipyard's tuple impls have a size limit. Each group is a "bundle" you could reuse (the core tuple is exactly what an elite and a leader also need).

Note the shared core. Health, BaseStats, Status, StatStages, Body and Species are built the same way in both constructors. A real port would pull them into one mon_core(entry, size, level, max_hp) helper. Today that sharing lives in G.Stats plus copy-pasted field setup.
Bench as data: a benched mon keeps its HP, moves, cards and status. It just has no Transform, so movement, collision and targeting skip it automatically. Swapping moves two tags.

8. Systems that use them

A system is a plain function. Its arguments say which components it reads (View) and writes (ViewMut), and it runs on every entity that has all of them.

The thing you've been working around: that test runs the actual damage path with nothing stubbed, because apply_damage can't call FX or Audio. It doesn't know they exist. Today's harnesses stub them or skip the real hit path. (The seed = 42 line is pseudo-syntax for "build a test world with this seed".)

10. What changed versus the JS

  • No presentation in constructors. No Animator, no sprite reads. Godot builds visuals from Species + Body.scale.
  • Fields become types. Today's 105 to 109 loose fields per class become about 15 named structs, each with one job. A system's argument list documents exactly what it touches.
  • "Is this a player?" disappears. Systems match on components, so a wild-only rule can't accidentally hit a leader, and a player rule hits leaders automatically.
  • HP has one writer. Everything queues a DamageEvent; only apply_damage subtracts, and it emits the hit event. That's the hurt() split from SIM-PRESENT-BOUNDARY, enforced by the borrow checker.
  • Save migration gets mechanical. Adding #[serde(default)] to a new field means old snapshots load with the default value, which replaces the hand-written null checks.
  • The cost: more ceremony up front (two-step spawn, explicit borrows, a queue instead of a direct call), and anything that wants to touch two entities at once has to go through an event.
